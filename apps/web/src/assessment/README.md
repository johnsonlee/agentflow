Portfolio ZIP exports a detached, oldest-first snapshot of every current photo, including the caption currently visible in the Portfolio. Export never writes the Portfolio, world, inventory or Camera journal. Closing the screen, changing the active writer or entering Camera recovery cancels pending work. An empty Portfolio has no export.

The local archive contains safe ordinal `photo-0001.jpg` names and UTF-8 `captions.json`. The sidecar is an AgentFlow format, not a Minecraft format claim. JPEG originals retain their bytes after local decode validation. Legacy PNG/WebP photos convert locally to JPEG at their intrinsic aspect ratio, with transparency composited over white. Any failed photo aborts the whole download; no partial archive is presented. App limits are 24 photos, 32 MiB input/archive and 16,777,216 pixels per photo. Stored ZIP entries include CRC-32; no remote service or extra runtime package is used.

Book photo insertion/text/signing use the existing BookScreen. Exact native ZIP ordering/caption conventions and native visual calibration remain separate gaps. CPU image mocks establish conversion/control flow only. Desktop/mobile download and actual JPEG visual verification require an independently executed final-version browser run.


Book PDF exports the visible detached draft or a signed read-only Book without committing, signing, closing, debiting or changing the original. Draft export is an application convenience; native export-before-signing has not been established. Current owner/factory session, writer, world-storage bytes, lifecycle and Camera journal must remain valid throughout. Cancel, lifecycle hide, a stale session, or decode/font/layout failure aborts the whole download. Done remains an explicit user close/commit action; export never calls it. Every initiated download retains its own idempotent URL cleanup until the 30-second retirement or hide.

PDF layout is an app-specific A4 document with logical-page labels and overflow continuations, not native parchment/font/format calibration. Empty logical pages and source order remain present. Valid orientation-1 gray/RGB JPEGs are embedded as original compressed streams after browser decode and header/dimension checks. Rotated/mirrored EXIF or CMYK inputs are explicitly normalized through browser-decoded pixels to RGB JPEG; converted images do not carry an original-byte claim. No source photo or Book metadata is rewritten.

Fonts load only when PDF export is requested, from hashed local assets. The pinned OFL Noto Pan-CJK Regular font supports the selected Latin/Chinese/Japanese/Korean coverage; the OFL Noto Emoji variable font supplies monochrome emoji outlines. Unsupported glyphs refuse rather than becoming tofu or disappearing. Straight supported text uses an embedded subset font. Emoji and text requiring shaped positioning/combining/ligature handling use lossless PNG runs painted from those bundled outlines; those runs are not searchable/selectable text. `book-text.json` is an app-specific exact UTF-8 attachment preserving original writing/captions, including grapheme sequences; PDF viewers vary in attachment access. No proprietary OS font or native Minecraft asset is copied. Font/library notices accompany the document and source.

The current new-photo model has 50 pages, 256 UTF-16 units per page and 8 photos. These are application limits, not native quotas. Export does not clamp exceptional legacy text; it wraps/continues or refuses whole output with the source unchanged. Export-only bounds are 8 MiB detached input, 1,000 logical/physical pages, 32 MiB image/font working bytes and final PDF, 60 seconds total and existing local image/font decode deadlines. Maximum-current-model and legacy-overflow correctness must be verified; these bounds are not performance acceptance.

Implementation-source status: no PDF output, compiler/unit/build or browser run is established by this source change alone. Font metadata/shaping probes do not establish visible glyph rendering, Unicode extraction or native equivalence. Independent final-version desktop/mobile download, standard PDF parsing, original-JPEG extraction/hash, every-page Poppler rendering and actual visual inspection remain required. The separate Book factory-loading fix must be integrated and independently verified before positive browser admission. Book page ZIP and Portfolio PDF are not implemented by this increment. Full Education features, graphics/distribution rights and native 26.33 per-platform PDF behavior remain open.
